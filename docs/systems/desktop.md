# Настольная оболочка и библиотека

## Ответственность и входы

`electron/main.cjs` создаёт одно окно. Пути из аргументов запуска, macOS open-file, повторного экземпляра, диалога и перетаскивания поступают в `Library`. Без файла показывается домашний экран; прежние вкладки не восстанавливаются. macOS-ветка реализована, но на macOS не проверена.

`electron/library.cjs` принимает `.md`, `.markdown`, `.mdown`, `.pdf`, `.docx` до 20 МиБ. Markdown читает как UTF-8/UTF-16 с BOM; PDF/DOCX передаёт как base64 с format. Кэш ограничен пятью последними файлами и проверяется по realpath, размеру, mtime/ctime. Неизменённый файл не перечитывается; preview Markdown строится из первых 8000 символов. Это проверенная оптимизация повторного чтения, не общий замер ускорения. Путь получается через realpath; Windows-сравнение учитывает регистр. Повторное открытие возвращает тот же id. Переуказание пути сохраняет id, позицию и закладки; дубликат назначения объединяется с исходной записью.

Нормальный размер — до 1120×800 и 82% рабочей области монитора; минимум до 560×420. Снятие максимизации/полного экрана возвращает нормальный размер. Проверены native maximize/unmaximize, выход из full-screen и размер половины экрана на Windows.

## IPC, ресурсы и безопасность

`electron/preload.cjs` предоставляет именованные операции: state, openDialog/openId/openRelative/relocate, pin/remove, settings/savePosition, add/rename/removeBookmark, saveSpace/removeSpace, image/external, drop, ready/flush и reset. Произвольного чтения файлов, исполнения команд и универсального invoke нет. Main проверяет отправителя, основную frame, источник и данные.

Окно использует nodeIntegration=false, contextIsolation=true, sandbox=true и webSecurity=true. Запрошенные разрешения, создание окон и произвольная навигация запрещены. CSP в `index.html` ограничивает скрипты локальной поставкой; встроенный HTML очищается в читалке. Основание: [рекомендации Electron](https://www.electronjs.org/docs/latest/tutorial/security).

`hawk-app://reader` обслуживает только dist. `hawk-resource` выдаёт изображения по непрогнозируемым токенам, привязанным main к пути открытого документа. Поддержаны PNG/JPEG/GIF/WebP/SVG/AVIF/BMP до 30 МиБ. SVG используется как img, без встраивания разметки. Относительные пути разрешаются от документа; сетевые пути и опасные схемы, включая закодированные сетевые пути, отклоняются. Только проверенные HTTP/HTTPS передаются системному браузеру.

При закрытии main просит renderer сохранить позицию и ожидает подтверждение. Аварийное завершение не гарантирует сохранения последней прокрутки; для неотвечающего renderer есть тайм-аут 5 секунд.

## Поставка и проверка

`package.json`, `scripts/package.cjs`, `assets/installer.nsh` создают Windows NSIS и portable. `scripts/verify-install.ps1` устанавливает в App, проверяет Open With всех пяти расширений и сравнивает Default/UserChoice до и после. При обновлении собственное открытое окно закрывается штатно с ожиданием выхода; принудительное завершение не применяется. Подготовлены macOS DMG и Linux AppImage/deb; сборки и запуск остаются неподтверждёнными.

Проверки: `tests/core.test.cjs`, `tests/e2e/reader.spec.ts`, [журнал](../verification.md). Ограничения: [known-issues.md](../known-issues.md). Изменения относятся к P1/P3/P6/P8/P9/P11/P12 в [плане](../plan.md).

## Установка и язык

NSIS показывает выбор из 15 языков установщика и записывает только LCID в installer-language.json рядом с exe. electron/locale.cjs ограничивает чтение 128 байтами и выбирает известный язык. Новый профиль получает выбранный язык, существующий сохраняет свой. Portable использует язык ОС. Бенгальского перевода NSIS в используемом runtime нет; বাংলা доступен в настройках приложения. Поддерживаются 16 языков интерфейса. При обновлении ассоциации по умолчанию сохраняются. copyText проверяет sender, тип и длину строки; чтение буфера в preload не открыто. Поставка включает GPL и THIRD-PARTY-NOTICES.

Сборка Windows проходит через scripts/package.cjs: известная пропущенная закрывающая кавычка в строке MULTIUSER_INNERTEXT_INSTALLMODE_CURRENTUSER из NSIS 3.0.4.1 Hindi.nsh исправляется только в локальном .verification/builder-cache. После первого скачивания допускается один повтор сборки. Системные установки NSIS не изменяются. Перед упаковкой после смены зависимостей выполняется npm run licenses.
