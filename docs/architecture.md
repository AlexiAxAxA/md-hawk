# Архитектура MD Hawk

## Настольная оболочка

`electron/main.cjs` создаёт одно sandbox-окно с contextIsolation и без Node в renderer. Все операции с документами выполняются в main. `electron/preload.cjs` предоставляет только именованные операции через contextBridge: библиотека, открытие/перемещение документа, закрепление/удаление истории, настройки, позиции и закладки, пространства, ресурсы и внешние ссылки. Входы и отправитель IPC проверяются.

Запуск с путём и событие macOS open-file поступают в общий обработчик. Повторный экземпляр передаёт файл первому. Открытие через диалог, drop, историю и ссылки приводит к тому же документу.

Точный контракт, ресурсы и Windows-регистрация описаны в [системе оболочки](systems/desktop.md).

## Библиотека и хранение

`electron/store.cjs`: состояние v3 с миграцией v1/v2 в каталоге Electron userData. DocumentRecord содержит id, нормализованный path, title, preview, lastOpened, pinned, position и bookmarks. Settings содержит theme, rememberPosition, fontSize, columnWidth, language, customColors, fontFamily, lineHeight и paragraphSpacing; пространства содержат ссылки на записи документов. Runtime-содержимое открытых файлов в JSON не сохраняется. Сохраняется только короткий preview и контекст позиции/закладок.

Записи сериализованы; temporary file + rename заменяют основной JSON. Последний корректный основной файл становится .bak. При повреждении основного загружается backup и пользователь получает сообщение. Если обе копии повреждены, запись блокируется, исходные копии сохраняются, приложение сообщает о проблеме. Явное восстановление создаёт отдельные архивные копии перед новым состоянием.

`electron/library.cjs` читает Markdown, PDF и DOCX, нормализует реальные пути и сохраняет идентичность при переуказании перемещённого файла. Локальные изображения выдаются через opaque URL, зарегистрированный после разбора ссылки относительно открытого документа; произвольные URL не предоставляют доступ к диску.

Поля схемы и поведение повреждённых копий: [система хранения](systems/storage.md). Main записывает синхронно, сериализуя мутации циклом событий; renderer сериализует изменения настроек очередью Promise.

## Читалка

React управляет адаптивным домашним экраном (размеры карточки зависят от свободной высоты, прокрутка остаётся у списка), вкладками, темами и панелями. Renderer получает DocumentData (record + content + format); бинарные документы передаются как base64. `Spaces.tsx` управляет группами, `i18n.ts` переводит интерфейс ru/en. Порядок вкладок изменяется без повторного чтения; Pointer Events ограничивают preview строкой, показывая тень и границу вставки. Детали — в системе читалки. `src/markdown.tsx` превращает Markdown в очищенное дерево, строит уникальные якоря заголовков, рисует KaTeX и Mermaid. Навигация по ссылкам обрабатывается приложением. `WordMarkdown` лениво загружает Mammoth, преобразует DOCX в HTML и пропускает результат через тот же sanitizer. `PdfReader.tsx` лениво загружает PDF.js и локальный worker: одна страница canvas с текстовым слоем, поиск и закладки страниц. PDF не запускает документные скрипты или формы. Ограничения форматов перечислены в known-issues.md.

`src/position.ts` сохраняет текст блока, контекст соседей, ближайший заголовок, смещение внутри блока и процент. Восстановление: текст/контекст → заголовок → процент с уведомлением. Изменение темы/шрифта/ширины и позднее изменение размеров документа восстанавливают текущую привязку. Пользовательская прокрутка обновляет её. Детали: [система читалки](systems/reader.md).

## Границы

Исходные файлы доступны только для чтения. Renderer не получает универсальный файловый или shell API. Внешние HTTP/HTTPS ссылки открываются после проверки схемы; JavaScript/data/file ссылки не исполняются. Для встроенных DOCX-изображений разрешены только ограниченные base64 PNG/JPEG/GIF/WebP в src; это не разрешение data-ссылок. У Mermaid строгий режим; HTML очищается до запуска компонентов KaTeX/Mermaid. Скрипты поставляются локально.

Проверенное поведение и ограничения перечисляются в plan.md и known-issues.md; будущие возможности не считаются существующей реализацией.

## Решения поставки

Windows устанавливает собственные OpenWithProgids и Capabilities без записи Default/UserChoice: стандартные fileAssociations упаковщика заменяли приложение по умолчанию. Поставка содержит bundled renderer и Electron; runtime node_modules не нужны. Подготовленные конфигурации macOS/Linux требуют проверки на этих системах.

Основой настройки изоляции и IPC служат [рекомендации Electron](https://www.electronjs.org/docs/latest/tutorial/security). Область выполненных проверок описана в [verification.md](verification.md); это не утверждение об отсутствии всех возможных уязвимостей.

Настройки и локализация используют общий `shared/preferences.json`, словари `shared/locales` и `electron/locale.cjs`. Renderer не читает буфер обмена: операция copyText записывает только проверенный текст. Подробности — [оформление и языки](systems/preferences.md).
